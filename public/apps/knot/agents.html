Agents and workspaces

Agents

An agent is a running AI coding CLI—Claude Code, Codex, Gemini CLI, GitHub Copilot, OpenCode, a shell, or a custom command—bound to a launch configuration that says which CLI to run and how. Knot talks to most agents over ACP (the Agent Client Protocol), and shows them through its own panel UI: chat, tool calls, and diffs render as structured turns rather than raw terminal text. Agent types without a registered ACP adapter still run in a terminal grid instead.

You can create, rename, select, close, restart, and reattach agents at any time. Reattaching picks a session back up rather than starting over.

Agent status

Every agent shows a live status so you can tell at a glance which ones need your attention:

  • Working: the agent is actively running.
  • Idle: the agent is waiting with nothing in progress.
  • Awaiting input: the agent needs a response from you before it can continue.
  • Error: the agent has hit a problem.

Workspaces

A workspace groups agents together, usually around a single repository or project. Like agents, workspaces can be created, renamed, selected, closed, restarted, and reattached.

Knot discovers Git repositories and their linked worktrees on disk, and surfaces each one's status, diffs, and change statistics, so you can see what an agent has changed without leaving the app.

Coordinating multiple agents

Knot runs a local MCP server so agents can message each other and share context instead of working in isolation. This is useful when you want to split a task across several agents, or have one agent hand work off to another.
